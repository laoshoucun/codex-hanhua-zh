# Codex 设置中文不生效？官方其实早就做好了中文

> 原文链接：[https://www.sz003.com/codexh/2680](https://www.sz003.com/codexh/2680)

设置里把语言切成中文，退出应用再打开，菜单栏还是英文。这件事在 Codex 桌面端上不算新鲜，碰到的人不少。有人以为是自己重启得不干净，有人去删缓存，还有人干脆重装了一遍，回来一看，界面还是原样。

先说结论：这不是你操作的问题。官方客户端里早就放好了中文，只是加载中文的那个开关没被打开。往下把这层拆开讲，最后给一条眼下能走通的路。

选了中文，重启回来还是英文

有人把这个情况报到了 OpenAI 的代码仓库，issue 编号 27411。报告里写得挺细：macOS 环境，系统语言本来就是中文，config.toml 里也老老实实写了 localeOverride = "zh-CN"，重启之后界面照样是英文。

同一份报告里还有一句更要紧的话。把客户端解开之后，里面能数出 15632 条不重复的中文界面字符串。翻译早就做完了，界面上就是不用。

界面没变中文，不影响它用中文答你

菜单栏，设置页，按钮，这些是界面语言，归客户端自己管。你问一句、它回一段，那是回复语言，归模型和你的提示词管。

两件事可以分开。界面还挂着英文的时候，你完全可以让它全程用中文回答，代码解释，报错分析，文档生成，都不受影响。所以看到设置没反应，不用把整个客户端当成坏的。

我到今天也没完全弄明白官方的本地化排期，这块只能按公开信息说。

中文资源一直在，缺的是加载这一步

公开的分析里给了两个方向。一个是有人拆开客户端看到过翻译包，中文那份 js 有将近一兆，菜单本地化另有一份 json，东西都在包里躺着。

另一个是加载逻辑读的是一个远端配置开关，默认关着。开关不开，翻译包就不参与加载，设置页里的语言选项有时候干脆是灰的，甚至不显示出来。还有开发者顺着代码往下看，发现网页壳那一层初始化的时候把语言写死成了 en-US，配置文件里的值读到了，用的时候没用上。

这几个说法来自公开的仓库讨论和实测记录，不是官方口径，但能解释大家看到的现象。

现在能走通的一条路

官方的口子什么时候开，没人给时间表。眼下能走的是另一条路：不动客户端，只把读配置的那一层喂上中文。

要不要装汉化包，答案就落在这里。判断标准也简单，看它动不动官方文件。站上这个汉化专题提供的汉化包，做的就是在启动之前把 desktop.localeOverride = "zh-CN" 写进官方配置，再按本机装的版本对一份兼容清单。版本对上了走中文工作流，对不上就保留官方原来的界面，提示等适配。

先做的一件事

打开客户端，翻到 About，把版本号记下来。带着这个号去汉化栏目对着清单看一眼。版本在里面，装完重启一次界面就是中文。不在里面，把版本号留着，等清单更新，比反复重装有用。
